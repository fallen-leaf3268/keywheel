# 短按输入回放设计

## 目标

让短按主功能和普通短按批量功能与轮盘选择使用相同的目标隔离原生输入回放，使监听 Forge 原始键盘或鼠标事件的正常 `KeyMapping` 功能也能通过短按触发。

## 行为约束

- 短按时机、长按阈值、轮盘操作、交换模式、锁定和保持长按行为不变。
- 单目标短按只触发指定 `KeyMapping`。
- 批量短按保持现有目标顺序，每次回放只允许当前目标响应。
- `KEYSYM` 和 `MOUSE` 使用原生输入回放。
- `SCANCODE`、未绑定键或客户端入口不可用时继续使用现有 `clickCount/setDown` 路径。
- 不包含第三方模组 ID、按键 ID 或专用适配器。
- 不新增网络协议，继续保持纯客户端。
- JAR 只输出到 `C:\Users\Lenovo\Desktop\Ai_Run\output`，不部署到 `mods`，不上传 GitHub。

## 执行流程

`ActionExecutor.run` 和 `runBatch` 捕获目标当前物理键。支持回放且客户端可用时，将目标依次交给统一的一次性回放方法：发送 PRESS，记录目标与捕获键，并由现有 Tick 清理入口在下一 Tick 发送 RELEASE。

批量执行不合并为一个物理事件。每个目标使用独立、同步、短生命周期的 `SyntheticInputContext`，因此同一物理键上的其他映射在该次事件中不可见；当前目标处理完成后上下文立即清理，再处理下一个目标。

轮盘功能继续使用现有延迟回放入口。短按发生在物理键已经释放、`LongPressWatcher` 判定为短按之后，因此无需再次延迟到界面关闭。

## 状态与清理

短按回放与非保持轮盘动作共用一次性释放表，保存映射身份和捕获键。下一 Tick、成员清理或配置变更时发送匹配的 RELEASE，并最终执行 `setDown(false)` 兜底，避免第三方状态或 `KeyMapping` 状态滞留。

如果目标在执行前已经改绑或从当前键位表移除，则取消该目标。若原生入口在事件分发前不可用，则回退旧执行方式；事件分发开始后的异常视为已处理，避免再次回退造成双触发。

## 测试标准

- 测试先证明 `run` 和 `runBatch` 尚未引用原生回放路径。
- 验证单目标和批量短按都进入统一一次性回放策略。
- 验证支持类型选择回放、不支持类型选择旧路径。
- 验证批量目标保持原顺序且逐目标隔离。
- 现有轮盘延迟回放、短按判定、锁定、保持长按和缓存回归全部继续通过。
- 最终执行 `clean check build`，检查重混淆 JAR 的类、Mixin、refmap、客户端标记和 SHA-256。
